## 4. 视觉方案：沿首页入画，借参考图成图

### 4.1 视觉变量

在新样式中定义带 `--habitat-` 前缀的变量，避免与旧页面的全局变量冲突。

| 用途 | 推荐值 |
| --- | --- |
| 页面墨绿底 | `#171c1b` |
| 次级墨绿面 | `#232c29` |
| 米色正文／纸面 | `#f3e6ca` |
| 古金细线与强调 | `#dbb879` |
| 朱红热点与主操作 | `#a82320` |
| 深朱红选中块 | `#6b1818` |
| 深色背景辅助文字 | `#bfc0ad` |
| 地图陆地 | 暖米色，可由纸面色微调 |
| 地图水域 | 低饱和青蓝、青绿，与墨绿页面协调 |
| 浅纸背景正文 | 深墨色，辅助字保持可读对比度 |

标题沿用首页字体序列 `STXingkai, STKaiti, KaiTi, serif`；正文参考 `Noto Serif SC, Songti SC, SimSun, serif`。使用系统字体回退，不依赖在线字体。正文一般 16px，辅助文字一般 14px；地图必要标签在屏幕上至少约 12px，手机主要地名至少 14px。

### 4.2 地图构图

必须先打开参考图进行视觉比对。基于它重新绘制可交互的原创示意图，保留以下可辨识结构：

1. 接近圆形的外轮廓，有墨青与古金细环。
2. 曲折的外围陆带，至少有一处开口或明显海湾，避免画成规整同心圆。
3. 中央独立山陆与内海，辅以小岛、湖泊或水道。
4. 青绿山群、墨线山脊、少量树木、水纹及古籍式题字。
5. 散布在山陆或水域附近的朱砂热点，选中时配金色外圈与题签。

初始视觉坐标为 `0…1000 × 0…1000`，圆心约 `(500, 500)`，主体控制在约 `60…940` 范围，给外环和标签留空隙。外围陆带、中部山陆与水域使用不规则曲线，不用默认地图组件的矩形网格风格。

构图中的方位与山水轮廓属于视觉创作。按经篇组织的点位可在南、西、北、东、中区域形成阅读分布，海荒点位作为独立图层处理；这不表示将神话地名对应到真实地理，更不能由图面距离推导古籍里程。海荒与山经之间不绘制统一考察路线。

### 4.3 素材与图层规则

- 地形轮廓、岛屿、山形、路线、地名分别可编辑；地名与点位文字保持真实文字。
- 以 SVG 路径、重复山形图案、已有纸纹和水纹完成底图，不需要生成新的位图图片。
- 参考图仅作设计参考，不把整张带红点和文字的图片叠上另一套热点冒充成品。
- 现有 `map-hero-ancient-routes.png` 可以低透明度用于页脚或背景，不作为新的交互底图。
- 装饰云纹、细金线和印章保持克制；避免密集描边、厚重立体边框、大面积红色标题栏和发光效果。
- 不添加无来源的著名神山、神兽名或知识性注释来填满地图；没有内容依据的山形属于无名装饰。

## 5. 页面结构与尺寸

### 5.1 桌面 `map.html`

从上到下按这个顺序实现：

1. **页头**：品牌与首页同款卷轴导航。导航依次为“入画／神兽图鉴／山海舆图／文化寻踪／原典摘读”；当前项为“山海舆图”，使用 `aria-current="page"`。
2. **面包屑与短标题**：`入画 / 山海舆图`；主标题“山海舆图”；副文案“循山川之迹，寻异兽之所。”；补一行“神话地理与相对位置示意”。
3. **探索工具栏**：经篇切换、神兽／地名搜索、“更多筛选”。
4. **探索主区**：左侧大地图，右侧异兽手札。地图至少约占可用宽度的 65%，手札约 300–340px，列间距约 28–36px；容器上限约 1440px。
5. **山海名录**：展示筛选后的异兽记录，可点击定位；桌面 3–4 列，按实际宽度收缩。
6. **资料与地图说明**：用一个紧凑说明区和可展开内容解释来源、核实状态、视觉坐标及路线含义。
7. **页脚**：沿首页的墨绿山影与米金文字，保留栏目及资料入口。

在 1400×900 附近，页头与标题合计尽量控制在约 250px 内，首屏能直接看到地图与可用点位。不给地图前面安排占满一屏的横幅。

地图保持正方形画布和完整环形构图，按所在列等比例适配；不通过固定最小宽度迫使页面溢出。手札正文随页面滚动，可使用留有页头间距的 `sticky`，但不得变成高度不足、内容不可达的内部滚动框。

### 5.2 工具栏与筛选

- 经篇：全部、南山经、西山经、北山经、东山经、中山经、海荒经。小屏改为带标签的原生选择框。
- 搜索框占据足够宽度，提示“搜索神兽、山名或关键词”，旁边提供“清空”。
- 更多筛选用原生 `details/summary` 或等价可访问展开控件，放置“异兽类型”“资料状态”“显示地名”“显示浏览路线”。
- 类型来自经过整理的现有数据；注明其为网站的浏览分类，不能声称为原典分类。
- 资料状态使用“全部资料／已核对原文／待核实”。如果尚无核实项，“已核对原文”显示 0 条并正确出现空状态。
- 默认显示地名；默认关闭浏览路线；不提供相对坐标网格。
- 计数明确区分“地点”与“异兽记录”，如“22 处地点 · 23 条记录”；数值从数据实时计算。

### 5.3 手机与平板

- 约 1000px 以下，地图与手札改为单列；约 760px 以下使用移动导航。
- 手机顺序：页头 → 标题 → 紧凑筛选 → 地图 → 所选异兽摘要 → 展开手札 → 名录 → 说明与页脚。
- 地图全宽，保留正方形完整轮廓，不能裁成只剩中间一块。
- 初始只显示少量主要地名和选中地名；放大后再显示更多标签。
- 不采用遮住地图的大型底部弹窗；摘要与详情在正常文档流中展开。
- 名录在 390px 下按一列或可读的两列排版，不以过小文字强行凑列。
- 390px、360px、320px 页面无横向滚动；筛选、按钮和长地名可正常换行。
- 地图上的朱砂点可小，但独立热点的有效点击区域约 44×44px；空间不足时合并临近热点，不允许看不见的点击区域互相遮挡。

## 6. 交互行为与状态规则

### 6.1 初次进入

- `map.html` 无参数时展示全图与全部记录。
- 默认手札选中九尾狐，默认地图仍为全图，不立刻放大。
- 显示地点数、记录数、简短图例与操作说明；图例不堆叠现有七种彩色圆点。
- 桌面地图操作：拖动、滚轮缩放、按钮缩放、览全图、聚焦所选地点。
- 移动端默认可正常纵向滚动页面；点位点击与缩放按钮始终可用。

### 6.2 点选与悬停

- 鼠标悬停或键盘聚焦显示简短题签“地点 · 异兽”；移出后收起，题签不能超出地图边界。
- 点击地点高亮朱砂点与金圈，适度聚焦并更新手札、名录选中项及 URL 状态。
- 同地点多异兽只绘制一个热点，手札显示该地点可见异兽的选择按钮。例：邽山选择蠃鱼／穷奇；分类或搜索过滤后只显示匹配成员。
- 选择同地点的另一只异兽时只更新内容，不反复缩放地图。
- 不根据鼠标悬停改变正式选中项，也不持续向读屏软件播报悬停内容。

### 6.3 搜索与筛选

- 搜索覆盖神兽名、别名、地点名、经篇标签及已整理的关键词，使用去首尾空格的文本匹配。
- 经篇、类型、资料状态、关键词采用 AND 关系。
- 搜索输入后更新结果，可约 150ms 防抖；不要每次输入都强制移动地图或滚动页面。
- 当前记录仍匹配时保持选中；不匹配时选中匹配结果第一条。
- 经篇切换或点击名录结果后可对匹配地点计算合适视野，不机械放大到第一条。
- 无结果时：热点和名录清空、计数为 0、手札显示“未找到匹配内容”，同时提供“清除全部筛选”；不能保留旧神兽详情制造误导。
- “清空搜索”只清关键词；“清除全部筛选”恢复默认筛选；“览全图”只恢复相机，三者含义清晰。
- 选择“全部经篇”时保持其他条件不变。

### 6.4 缩放、拖拽与手机手势

- 相机缩放范围 `1…3`；按钮步进约 0.25；缩放按钮有文字或可访问名称。
- 鼠标滚轮以指针处为锚点缩放，达到边界后不继续放大或漂移。
- 滚轮只在地图画布内接管；触控板或键盘触发的浏览器页面缩放保持可用，尤其不拦截 `Ctrl/Meta + wheel`。
- 使用 Pointer Events；累计位移超过约 6px 才进入拖动态。拖动结束不触发点位选择。
- 正确处理 `pointerup`、`pointercancel`、`lostpointercapture`、多指增减和窗口失焦，不能出现松手后仍拖动。
- 指针坐标通过真实 SVG 坐标转换，处理等比例留白，不能直接用页面宽度猜算。
- 移动端提供“操作地图／完成操作”切换。默认 `touch-action` 允许页面纵向滚动；开启后只在地图区域启用自定义单指拖动和双指缩放，完成后恢复页面滚动。
- 状态切换应有可见提示；“完成操作”控件始终可达，不能被地图层遮住。
- 双指缩放围绕两指中点，并在其中一指离开后重新设定拖动基准。
- 限制相机边界，防止整张地图被拖离画布；窗口尺寸或方向改变后重新布局、校验边界和热点位置。

### 6.5 标签与密集热点

- 地名采用独立文本层，根据相机缩放与屏幕碰撞情况决定可见性。
- 优先级：选中地点 > 搜索匹配／聚焦地点 > 主要地点 > 其他地点。
- 全图状态不要求同时显示全部地名；完整记录通过名录可达。
- 标签不能覆盖主要控件、切出画布、与邻近标签明显重叠，不能靠缩小到不可读解决。
- 不同地点在窄屏全图下若热点有效区域重叠，使用地点簇按钮显示数量；点击后放大到该簇，必要时在手札列出其中地点供选择。
- 地点簇不能把多个地点伪称为同一山名；聚合规则基于屏幕距离，每次缩放或容器变化后重算。

### 6.6 浏览路线

- 本轮提供的是主题浏览路线，默认关闭。选择经篇且打开“显示浏览路线”后，才显示对应浏览连线。
- 路线以独立数据中的有序地点数组定义，不直接使用旧 `order` 或旧 `routeGroup` 推导原典顺序。
- 未有原文顺序依据时，统一标注“主题浏览路线”，并说明“连线表示本站浏览顺序”。
- 山经与海荒经不跨层连线；海荒经本轮只显示点位，不声称拥有山经式考察路线。
- 筛选时只显示两端均可见的既有相邻线段，不跨过被隐藏节点重连并暗示新关系。
- 使用细朱红或古金线，选中时强调相关部分；不做无限滚动虚线或持续闪烁。

### 6.7 无障碍与动态效果

- 页面包含跳转主内容链接、逻辑标题层级、真实按钮和表单标签。
- 地图视觉 SVG 配套简短文字说明；交互使用原生 HTML 按钮，另有完整名录作为等价入口。
- 不在包含交互后代的父元素上使用 `role="img"` 或 `aria-hidden` 使按钮从可访问树消失。
- 点位、名录和异兽切换可通过键盘操作；选中状态可感知，焦点清楚。
- 更新详情时只用一个简洁 `aria-live="polite"` 状态播报，不让整篇原文或每帧缩放反复播报。
- 普通更新不重建当前聚焦控件导致焦点丢失；更新过后必要时恢复到原按钮。
- 轻微过渡约 150–300ms，遵守 `prefers-reduced-motion`；不安排持续自动运镜、漂浮、闪烁或背景音乐。

### 9.2 样式与脚本边界

- 样式以 `.habitat-page` 和 `.habitat-detail-page` 为页面根作用域；新变量使用独立前缀。
- 从首页提取必要的视觉写法到新样式中，不修改首页样式来迁就栖息地。
- HTML 使用普通脚本并加 `defer`，顺序为数据 → 公共逻辑 → 页面逻辑；不使用必须通过网络加载的 ES module 或运行时 `fetch()` 读取本地 JSON/SVG。
- 公共逻辑使用一个有命名的命名空间；页面初始化前判断对应根元素，避免相互误运行。
- 导航菜单独立实现窄屏展开、Escape 关闭、点击外部关闭、窗口变宽时复位，保证默认加载失败仍有可达的栏目入口。
- 全部资源使用相对路径；参数化页面在 `file://` 和 HTTP 本地预览两种方式下都能加载。
- 不依赖存储能力保证核心行为；`sessionStorage` 的读写放在异常保护内。

### 9.3 地图绘制与热点方案

推荐采用内联 SVG 画地形与路线，外层相对定位容器放原生 HTML 热点按钮：

1. SVG 固定基础 `viewBox="0 0 1000 1000"`，地形、路线、标签位于同一相机 `<g>`。
2. 相机只修改 `translate(tx, ty) scale(zoom)`，地形层不在每帧重新创建。
3. 对地点位置使用相机组的 `getScreenCTM()` 和 `DOMPoint` 转为屏幕坐标，再减去地图容器边界获得按钮位置；不靠近似比例对齐。
4. 原生热点按钮位于按钮覆盖层，以屏幕像素维持有效点击大小；覆盖层空白不拦截拖动，按钮本身可点击与聚焦。
5. SVG 视觉可对辅助技术隐藏；地图容器与原生热点、名录提供可访问说明。隐藏仅作用于视觉层，不隐藏按钮层。
6. 拖动时按 `requestAnimationFrame` 更新相机、热点与必要标签；不重新渲染整页、列表和手札。
7. 相机约束与适配以真实地图视口为依据；按钮、标签和外环始终对齐。
8. 通过 `ResizeObserver` 处理容器变化；缩放后重新判断热点聚合与标签避让。

坐标运算遵循“指针屏幕坐标 → SVG 坐标 → 世界坐标”的明确转换。以当前指针世界坐标为缩放锚点，计算新缩放与平移后再约束边界。若改变上述实现，只要保持离线可用、原生交互可访问与这些验收行为即可。

### 9.4 状态与 URL

维护统一状态：经篇、类型、资料状态、关键词、地名显示、路线显示、选中记录和相机。筛选结果与地点分组由数据和状态计算，避免多个模块各自维护一份结果。

规范地址参数：

| 参数 | 用途 | 示例 |
| --- | --- | --- |
| `point` | 异兽记录 ID | `qingqiu-jiuweihu` |
| `chapter` | 经篇筛选 | `south` |
| `category` | 类型筛选 | `beast` |
| `review` | 资料筛选 | `all` / `verified` / `pending` |
| `q` | 搜索词 | `九尾狐` |
| `labels` | 地名显示 | `1` / `0` |
| `route` | 浏览路线显示 | `1` / `0` |
| `z`、`cx`、`cy` | 相机缩放与世界坐标中心 | 有界有限数值 |
| `place` | 详情页地点 | `qingqiu` |

使用 `URLSearchParams` 编码；数值、枚举和 ID 均验证，非法值回退为合法默认，不出现 `NaN` 或运行异常。普通交互用 `history.replaceState` 更新，滚动和拖动不不断增加历史条目；手势结束再写相机状态，搜索输入更新作防抖。

详情页链接携带上述经过验证的地图参数，并额外加 `place`；返回时仅构造本站的 `map.html?...`，不接受任意外部 `returnUrl`。首次从明确的 `point` 深链进入且没有筛选参数时，显示全部并聚焦该记录；若筛选组合与记录冲突，则维持筛选并选择可见结果，详情与高亮始终一致。若存在相机参数，优先恢复经过校验的相机。

`history.replaceState` 在本地文件协议受限时，降级为可用的站内链接和尽力而为的 `sessionStorage`，不报错。详情入口携带当前真实状态，因此即使浏览器限制存储，仍能返回正确筛选和地点。

### 9.5 无脚本降级

- `map.html` 无 JavaScript 时仍显示首页式导航、静态环形地形和说明，并提供青丘地域详情、图鉴、原典入口。
- `habitat-detail.html` 无脚本时至少保留青丘静态内容与返回地图入口，说明启用脚本后可切换地点。
- 未启用脚本的交互控件隐藏或禁用并解释，避免出现看起来能操作的空按钮。

15. 按地点参数实现地域标题、概览、共享底图局部、相关异兽、地域导航和资料说明。
16. 实现进入详情、返回地图的筛选／点位／相机状态恢复，验证非法参数和直接打开的情况。
17. 完成来源记录、内容审计和实际验证记录；全局检查链接与素材路径。
18. 完成下一节验收，对发现的问题修复并复查，最后交付可浏览页面、截图和剩余待核实事项。

每阶段完成后继续下一阶段，不停在仅有布局、静态效果图或只描述后续计划的状态。执行过程中不主动扩大为站内其他板块的重构。

### 11.3 关键场景

| 操作 | 必须出现的结果 |
| --- | --- |
| 直接打开 `map.html` | 全图、默认九尾狐手札、全部记录、正确计数 |
| 点击凤凰地点 | 地图、手札、名录同步，独立详情入口对应凤凰 |
| 搜索“九尾狐” | 只有匹配结果，点位与手札一致；清空后恢复其他匹配项 |
| 搜索一个不存在的词 | 0 结果、无旧详情残留，可清除全部筛选恢复 |
| 切经篇再选类型 | AND 筛选正确，视野与选中合法，不残留隐藏记录的详情 |
| 搜索“邽山” | 一个地点，两条记录可切换；如果核实更正，其经篇标签同步正确 |
| 选择没有核实条目的资料筛选 | 正确显示空状态，不冒充有原文已核实记录 |
| 放大、缩小、聚焦、览全图 | 都有实际效果，边界合法，览全图不清除其他筛选 |
| 缩放后拖动并松手 | 热点与地形对齐，松手停止，拖动不误选地点 |
| 手机默认在地图上纵向滑动 | 页面可滚动，不被地图困住 |
| 手机开启操作地图、双指缩放、完成 | 地图响应，离开模式后恢复页面滚动 |
| 手机点击密集地点簇 | 可放大或逐个选择地点，没有互相覆盖的隐藏点击区 |
| 进入某地点详情再返回 | 所选记录、筛选与相机恢复，返回不指向固定青丘 |
| 无参数打开地域详情 | 显示青丘默认内容与可用返回入口 |
| 非法地点、记录或相机参数 | 友好降级，不显示 `undefined`、`NaN` 或抛异常 |
| 刷新带参数地图链接 | 正确重建状态与合法视野 |
| 仅键盘操作 | 菜单、筛选、名录、地点及详情入口都可达，焦点明显 |
| 开启减少动态效果 | 关闭自动与非必要动画，所有功能仍可用 |
