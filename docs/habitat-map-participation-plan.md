# 栖息地地图参与感改进方案

日期：2026-10-19。状态：**规划稿，尚未实施**。本次只新增方案文档，网站页面、正式数据和交互代码保持当前版本。

## 1. 本轮目标与现状判断

本轮将现有山海地图发展为可以亲自探访、观察并留下记录的画卷。参与感主要来自四件事：**有可理解的目标、有自己做出的选择、有及时可见的反馈、有能够再次接续的成果。**

已阅读项目说明、协作约定、来源说明，以及当前 `map.html`、`habitat-detail.html`、共享工具和地图脚本。当前已有 23 条异兽记录、22 个地点、14 个山系／海荒篇章分组、5 条经文相邻边、2 个经文辅助节点；缩放、拖动、筛选、手札、详情往返等已实现。

| 当前体验 | 参与感缺口 | 本轮回应 |
| --- | --- | --- |
| 用户打开地图后看到地点与筛选 | 缺少“我现在可以做什么”的具体目标 | 提供一条可选的短探访，让用户从一条经文线索出发 |
| 点击朱砂点后，手札切换到资料 | 用户动作与画面变化之间的反馈偏弱 | 将定位、到达、环境观察与收录设计成不同的反馈 |
| 经文路段可点开阅读 | 路线尚未形成由用户推进的过程 | 用户根据方位选择下一站，确认后推进探访 |
| 地点与异兽始终以同样的状态呈现 | 用户看不出哪些地方自己来过 | 增加“未访／已访”和“未收录／已收录”，文字与形状同步区分 |
| 只有视图参数保存在 URL 和会话快照中 | 缺少持久的个人探索记录 | 新增浏览器本地手札、完成记录和继续探访入口 |
| 手机上手札位于地图下方 | 点击后可能不易察觉选中结果 | 地图下即时显示精简结果和明确的阅读入口 |

优化范围仍限于栖息地两页及直接依赖，不启动全站重构。保留原有页面地址、全部记录 ID、旧脚本和素材。本方案不涉及账号、后端、社交排名或现实地理定位。

## 2. 推荐体验：自由览图＋循迹探访＋我的手札

地图保留两种阅读方式：“自由览图”和“循迹探访”。“我的手札”作为查看个人成果的入口，不再增加一种地图模式。

### 2.1 自由览图

默认保留完整地图、搜索、筛选、名录和资料阅读。用户可以直接查找任意异兽，不需要先完成探访或答题。

首次打开时，在地图上方放一条轻量的邀请：“从一条经文线索，开始你的山海探访。”主按钮“开始一次探访”，旁边可选“自由览图”。不使用覆盖地图的强制教程。

从旧链接或详情返回的用户优先恢复原位置；不因首次出现新功能而跳走。已经有记录时，同一位置改为“继续上次探访”，附一个简短进度，如“南山首段 · 已到堂庭”。当前山系有探访时优先推荐对应内容，否则推荐入门探访。

### 2.2 循迹探访

探访是本站设计的阅读活动。活动名称、观察问题、印章是网站设计；经文、方位和地点关系沿用已核对数据，两者在说明中分清。

一轮体验按照以下顺序推进：

1. **领一条线索**：读到短原句或一项观察目标，知道起点、要观察什么及当前进度。
2. **自己找一找**：在地图或等价的地点选项中选择下一站；系统不替用户自动依次播放。
3. **到达并观察**：画面适度聚焦，相关经文边被强调，水系或山上／水中关系出现对应反馈。
4. **主动收录**：用户点击“收入手札”，保存这条异兽记录；印章和计数即时更新。
5. **选择下一步**：可以继续下一站、停下来读原文、返回自由览图；离开后能够接着完成。

“已访”“已收录”“探访完成”分别记录。到达是浏览行为，收录是明确保存动作，探访完成由当前活动的步骤决定。观察题可跳过查看解析，不影响自由阅读和异兽收录。

### 2.3 我的手札

地图主工具区只放一个入口，例如“我的手札 · 已收录 3/23”。展开后在当前页查看：已收录异兽、已到访地点、探访记录，以及一条“继续探访”入口。默认显示收录列表，其他信息按需展开，不铺一排统计面板。

每条已收录记录可定位回地图、翻阅原文、进入地域详情，或写一段不超过 300 字的个人笔记。笔记明确标为“我的记录”，与古籍摘录分开。笔记是首版的次要功能，不能拖慢收录主流程。

## 3. 首版可直接采用的三次探访

首版沿用现有已核对内容，不为活动补造经文边、稀有度或异兽属性。时间为设计目标，需实际体验后调整。

### 3.1 入门：循西南访昆仑

- 活动 ID：`west-kunlun`；山系：`west-third`；预计 1—2 分钟。
- 使用地点：`huaijiang`、`kunlun`；异兽：`huijiang-yingzhao`、`kunlun-luwu`。
- 唯一经文边：`huaijiang-kunlun`，即“西南四百里”。

| 步骤 | 用户看到什么 | 用户亲自做什么 | 系统反馈及记录 |
| --- | --- | --- | --- |
| 出发 | 槐江的英招线索、原文和“从此向西南寻下一站” | 点选起点，点击“从槐江出发” | 标记槐江已访；仅在明确收录时保存英招 |
| 循向 | “西南四百里，曰昆侖之丘”及北向标记 | 在局部图或地点选项中选择昆仑 | 沿已核对边强调一次方向，聚焦昆仑，显示“已到昆仑之丘” |
| 观察 | 陆吾原文“虎身而九尾，人面而虎爪” | 可选辨认“九尾”对应哪项形态，也可直接查看解析 | 显示本条依据，不采用插图猜测；答错时给原文提示，可重试 |
| 留痕 | 陆吾资料与“收入手札” | 主动收录，或选择先读原文 | 收录出现一次朱砂印记；明确点击“完成本次探访”后生成个人完成记录 |

原句可以直接出现地点名，目标是让使用者亲自按方位完成阅读，不靠隐藏资料制造谜题。选择其他地点时允许先读其手札，当前探访保持在原步骤，并提供“回到当前线索”。

章莪—阴山仍是另一独立片段；不在此活动中连到昆仑，也不暗示这是一条完整西次三经行程。

### 3.2 循经：南山四站

- 活动 ID：`south-four-stops`；山系：`south-first`；预计 3—5 分钟。
- 顺序：招摇 → 堂庭 → 猿翼 → 杻阳。
- 逐段调用已有 `zhaoyao-tangting`、`tangting-yuanyi`、`yuanyi-niuyang`，里数和引句不另写一套。
- 起点可收录狌狌，终点可收录旋龟；堂庭、猿翼只记为已读经文节点，不增加异兽数量。

用户每到一站，读一项简短名物或环境线索，再自行选择下一站。终点给出“旋龟在山中还是水中”的可选观察，依据杻阳条“其中多玄龜”。不以疗效或灾害叙事设计现实承诺。

青丘虽在同一山系，当前没有从杻阳直达青丘的相邻边。本活动结束后可“去青丘自由看看”，这属于用户导航，不绘制额外经文路线。

### 3.3 观察：一山两境

- 活动 ID：`guishan-two-habitats`；山系：`west-fourth`；地点：`guishan`；预计 1—2 分钟。
- 异兽：`guishan-qiongqi`、`guishan-luanyu`。
- 不设置行进路线，围绕同一地点的环境关系参与。

用户在局部图或并列文字按钮中主动选择“山上”“濛水·水中”，相应高亮山体或水线，并切换穷奇、蠃鱼手札。两个环境都亲自打开过即可完成观察；两只异兽分别收录，不会因到过一座山就自动收录两条记录。

观察提示示例：“牛形猬毛来自本条经文；插画是艺术演绎。”不能用当前插画判断原文正确与否。

## 4. 画面反馈与动效安排

参与反馈应对应用户的动作，每次操作只保留一个主要视觉重心。延续墨绿背景、纸面手札、金线和朱砂；不增加脱离画卷风格的彩色奖励面板。

| 动作 | 推荐反馈 | 建议时长与边界 |
| --- | --- | --- |
| 指向／键盘聚焦地点 | 题签、朱砂点和选中轮廓一并变化 | 120—180ms；重要信息点击同样可见 |
| 主动选择一个地点 | 适度平移、聚焦；手札标题同步更新 | 300—450ms；再次拖动、滚轮或触摸立即中断 |
| 在探访中选择正确下一站 | 只沿已有经文边描线一次，出现到达提示 | 450—700ms；不按动画推算速度和真实距离 |
| 观察山上／水中 | 相应山体或命名水线短时强调 | 200—300ms；不持续波动或闪烁 |
| 首次收录异兽 | 卡片落一枚朱砂印，计数加一 | 250—400ms；文字确认“已收入手札”，重复点击不重复增加 |
| 完成本次探访 | 生成一条可再次打开的探访记录 | 当前面板内展示，不弹全屏奖励窗 |

默认不播放声音，不增加持续运行的粒子、自动巡视或大范围视差。将“水声／环境声”列为后续选项，素材来源及创作性质核对后再做。

不把鼠标长按、擦除、精确拖线作为必要动作。全图不设置遮住地名的强制迷雾；可以用节点边缘的一笔淡墨、已访印记或可关闭的轻云区分个人探索状态。减少动态效果设置开启时，相机、描线和盖章直接呈现结果，保留文字与状态反馈。

## 5. 页面布局与交互冲突处理

### 5.1 桌面

保留地图主区域和右侧手札。主工具区将“自由览图／循迹探访”与“我的手札”安排为一条紧凑入口；经篇、山系仍在原位置，类型和图层继续放在更多筛选里。

活动开始后，地图上方只出现一条当前线索，例如“循西南访昆仑 · 2/3：按经文找到下一站”。其中“2/3”只表示当前活动步骤，不能与异兽或地点总数混用。

右侧手札新增简短的到访状态、“收入手札”按钮和下一步。长原文、版本说明、出处保留按需展开。当前经文路段卡继续可用，但不因为点开卡片就自动记录为已循行。

### 5.2 手机

顶部保留模式入口；线索条在地图前，地图之后紧接当前选择的精简卡：异兽／地点、环境关系、一句摘要、“收入手札”“展开手札”。点位选择后更新精简卡并宣布选中结果，不强行把整个页面滚走。

展开完整手札采用页面流内面板，支持一键收起；不同时叠加底部弹层、地图操作浮条和浏览器键盘。继续沿用“操作地图／完成操作”来区分页面滚动和地图手势。

所有核心动作支持点击和键盘；地图选择必须有名录或文字选项等价入口。热点和触屏按钮有效区域至少 44×44px，地名与关键反馈不只依赖颜色表达。

### 5.3 随时离开与恢复

- 一次只有一个正在进行的探访。切换其他探访时暂存原活动，不清除其已完成步骤。
- 用户更改经篇、山系或切换到活动范围外时，暂停当前探访，显示“继续探访”；自由浏览照常使用。
- “继续探访”由用户明确触发，恢复该活动的山系和必要图层；活动开始前的浏览状态另存，可“回到刚才浏览”。不静默丢弃用户原搜索。
- 筛选隐藏了当前目标时，说明“当前筛选隐藏了探访地点”，提供“恢复探访视图”和“暂存后自由览图”。不把筛选无结果解释为任务失败。
- 正在执行的相机动画遇到手势即取消，当前相机值成为拖动起点，避免抢控制权。用户在完成提示出现时仍可立即点别处。

## 6. 状态、计数和保存规则

### 6.1 三种进度分开

| 进度 | 记录单位 | 触发条件 | 不触发的情况 |
| --- | --- | --- | --- |
| 已访地点 | 22 个正式地点 ID | 用户主动点选、从名录定位，或在活动中确认到达 | 首屏默认选中、页面刷新、浏览器前后退、仅程序定位 |
| 已收录异兽 | 23 个异兽记录 ID | 用户主动点击“收入手札” | 仅打开手札、经过地点、自动载入详情、完成一条路线 |
| 探访完成 | 首批 3 个活动 ID | 完成各活动必要步骤，再主动确认完成 | 直接改 URL 步骤、只打开结果面板、只选起终点但没有开始活动 |

2 个经文辅助节点与 5 条经文边分别记录已读／已循，不并入地点或异兽数量。活动观察题另存作答结果，可跳过解析，不决定自由收录资格。

已访、已收录属于个人阅读记录，不改变资料的“已核对／待辨”状态；收藏应龙也不会把住所疑点变为确定事实。

### 6.2 保存方式

沿用原有 URL 保存视图，新增本地进度独立保存，建议存储键为 `shanhai:habitat-progress:v1`。不将个人笔记、完整收录列表塞进 URL。

建议存储结构如下；它是实施约定，尚未创建实际数据：

```json
{
  "schemaVersion": 1,
  "visitedPlaceIds": [],
  "collectedBeastIds": [],
  "readContextNodeIds": [],
  "readPassageIds": [],
  "traversedEdgeIds": [],
  "completedTrailIds": [],
  "trailProgress": {},
  "activeTrailId": null,
  "notesByBeastId": {},
  "updatedAt": null
}
```

`trailProgress` 以活动 ID 为键，保存完成步骤 ID、观察结果和开始前浏览快照。步骤进度由真实动作产生。全部 ID 校验、数组去重、无效数据丢弃；读取损坏或旧结构时安全回退，避免渲染失败。

本地存储不可用时，在当前页面内维持进度并告知“本次记录暂存，关闭后可能丢失”，核心浏览、探访和收录继续可用。直接打开文件仍应工作；文件协议、不同预览端口和不同浏览器之间不承诺共享本地记录。个人手札内一句说明“记录保存在当前浏览器”。

“重新体验”只重置该次活动步骤，不删除收录或笔记。“清空我的手札”放在个人面板末尾，二次确认并明确将清除的范围。初次加载不自动抹除历史记录。

## 7. 可直接执行的文件改造安排

不引入构建工具、模块加载、地图平台或新的运行依赖。当前原生 HTML、CSS、JavaScript、SVG 架构足以完成首版。

| 文件 | 具体工作 |
| --- | --- |
| `data/habitat-experiences.js`（新增） | 登记首批 3 个活动、步骤 ID、目标地点、原有经文边 ID、可选观察问题与依据。优先引用 `habitats.js`，不复制一份山海事实数据 |
| `js/habitat-progress.js`（新增） | 本地记录加载、保存、校验、去重、内存降级、订阅更新、重置范围。地图与地域详情共用 |
| `js/habitat-explore.js`（新增） | 处理开始、选择下一站、观察、暂停、恢复、完成；显示线索条、活动选择与我的手札 |
| `js/habitat-map.js` | 为用户选择增加动作来源；增加程序导航接口、已访标记、可中断相机过渡，以及地图事件与活动进度联动 |
| `js/habitat-art.js` | 提供可单独强调的山体／水系标记和轻量到达反馈；保留装饰与有据环境的分层 |
| `js/habitat-common.js` | 增加共用收录按钮、必要的模式／活动参数；保留已有参数含义与来源组件 |
| `map.html` | 模式入口、探访线索条、我的手札面板、收录入口、手机精简卡；保留原导航、地图和名录结构 |
| `habitat-detail.html`、`js/habitat-detail.js` | 详情中的同一异兽可收录、写笔记，返回地图恢复活动；不将自动展示当作到访或任务完成 |
| `css/habitat-map.css` | 个人状态标记、轻动效、线索条、手札面板及响应式布局；减少动态效果适配 |
| `docs/habitat-map-validation.md`、`docs/source-notes.md` | 记录实际完成的体验、来源、素材与验证；规划未做内容不写成已实现 |

脚本顺序建议：`habitats.js` → `habitat-experiences.js` → `habitat-art.js` → `habitat-common.js` → `habitat-progress.js` → 对应页面脚本 → `habitat-explore.js`。详情只加载用到的共用脚本，不加载地图控制器。继续使用普通本地脚本，不使用本地 `fetch`。

### 7.1 与现有选择逻辑衔接

当前 `select()`、`selectContext()`、`chooseRoute()`、`render()` 的展示职责保留。新增明确动作来源，例如 `user`、`guided`、`restore`、`initial`，并通过小型事件／订阅接口传递稳定 ID，避免活动脚本根据手札 DOM 文字猜状态。

推荐事件包含：主动选择地点、主动打开经文边、确认活动到达、收录异兽、提交观察、暂停／恢复活动。事件携带地点／记录／边 ID、动作来源、活动与步骤 ID；只在行为入口发出，不在重复渲染、相机每帧或历史恢复时累计进度。

相机过渡统一走一个可取消入口，并继续同步热点、标签和 SVG。不要另叠一个只移动地形、不移动热点的 CSS 动画。活动视图与现有过滤结果矛盾时先处理目标可见性，不能出现“提示去找一个被筛掉的点”。

### 7.2 URL 与个人进度分离

如需可分享线索，新增 `mode=explore`、`trail=<活动ID>`，必要时增加 `step=<步骤ID>`。它们只决定打开哪项活动／线索，不能据 URL 写入“已完成”。活动步骤能浏览、能解释，但完成记录以本地动作验证为准。

旧 `point`、`chapter`、`series`、`view`、`category`、`review`、`q`、`passage`、`node`、`labels`、`route`、`text`、`environment`、相机参数继续兼容。浏览器前后退只还原视图和活动显示，不撤销已保存的个人收录，也不额外完成步骤。

## 8. 分阶段交付

### A：先完成一次有始有终的体验

落实“循西南访昆仑”完整闭环：模式入口 → 线索 → 用户选择 → 到达反馈 → 自主收录 → 个人手札 → 暂停恢复。同步做好本地进度、手机精简卡、键盘与存储降级。

完成标准：新用户无需讲解即可开始一次探访，主动找到昆仑、收录陆吾；刷新后保留成果，进入详情再返回仍可继续。不依赖补图、音效或全部活动来证明主流程。

### B：扩展首版覆盖并打磨画面

接入南山四站、一山两境；完成山体／水线观察、已访与收录标记、一次性盖章和路线反馈；补齐个人笔记和必要回归。

完成标准：首批 3 个活动可独立完成；上下游引用同一份原文和 ID；辅助节点和异兽计数分开；自由浏览和已有功能继续可用。**A、B 合起来是推荐的首轮实施范围。**

### C：后续增强

在首轮可用后考虑：导出个人游历卡、更多有来源的探访、可选环境声、同条经文的版本对照、更多原创局部图。每项新活动单独核对出处，每项素材单独登记来源。

迷雾、大范围天气、角色养成、联网排名、真实里程累计、要求收集全图才能阅读等均不纳入首轮。优先验证有目标的探索是否愿意让用户持续参与。

## 9. 执行后的验收要求

### 9.1 主体验与内容

1. “自由览图”可直接使用全部现有记录；探访、观察题和收录不阻挡阅读原典。
2. 新用户首次进入有一条清晰可选目标。15 秒内能理解第一步、约 60—90 秒获得第一次收录，作为可用性目标记录，不能在未观察用户之前宣称已经达成。
3. 入门探访由用户选择下一站推进；可暂停、重试、查看提示或中途自由浏览，不会被自动播放取代。
4. 西南、西向、东向与当前 5 条有据经文边一致；未录入片段保持断开，海荒不新增迁徙线。
5. 辅助节点有独立阅读反馈；邽山山上／水中对应正确。观察问题能定位到当前原段，不依赖有歧义的插图或待辨字段作唯一答案。
6. 首次收录仅加一，重复收录不增加。邽山两条记录独立；默认选中、刷新、前后退、详情自动载入不产生虚假到访或完成。

### 9.2 状态与边界

7. 活动开始、暂停、切换、恢复、完成和重新体验逐项操作；恢复前后不丢个人笔记和其他活动记录。
8. 刷新、关闭再打开、两页往返、多个同源标签页、存储关闭／满额／损坏均有确定行为；本地存储失败不阻断浏览。多标签页监听 `storage` 更新，合并不同 ID 的集合，不用过期快照覆盖新收录；同条笔记以各自更新时间处理并给出可理解提示。
9. 非法活动 ID、非法步骤、直接深链、筛选隐藏目标、搜索无结果、图片缺失均不造成死路或误计数。
10. “重新体验”与“清空手札”作用范围明确；笔记以纯文本呈现，不作为 HTML 执行。

### 9.3 设备与回归

11. 桌面约 1400px、手机 390px，以及 320／360／768／1024px 检查无横向溢出；关键动作无需悬停，触屏有效区至少 44px。
12. 双指缩放、单指拖动、页面滚动、点击识别保持原行为；动效中开始拖动立即获得控制权。聚合点与已访标记不冲突。
13. 键盘可开始、选择、收录、暂停、继续、关闭面板；关闭后焦点返回入口。到达和收录使用适度的状态播报，不逐帧播报动画。
14. 减少动态效果模式下无非必要过渡，所有步骤仍能理解与完成；默认不自动发声。
15. HTTP 本地预览与直接打开文件均检查；无新增资源或控制台错误。保留无脚本静态阅读降级，关闭脚本后不显示失效活动入口。
16. 完成原有地图及首页、图鉴必要回归；保存桌面／手机前后截图与一次完整探访的操作记录，报告实际通过项和未覆盖环境。

首轮是否成功，以“用户能主动完成一次探索、清楚知道自己做了什么、回来能接着走”为判断标准。单纯增加动画数量不能替代这些结果。
